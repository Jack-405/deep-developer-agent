# DeepDev 记忆约定

本文件是 deepdev 的全局出厂记忆（随 deepdev 源码分发，git 管理）。
它是记忆的三层来源之一，加载顺序固定为：全局 → 项目 → 运行时，后出现者覆盖先出现者。

## 记忆分层

1. 全局：`backend/memory/global/AGENTS.md`（本文件，随 deepdev 升级演进）
2. 项目：`<工作区>/AGENTS.md`（随项目仓库走，git 管理）
3. 运行时：`<工作区>/.deepdev/memory.md`（deepdev 私有，.gitignore 隔离，跨会话持久）

当前工作区的运行时记忆文件虚拟路径为：`/.deepdev/memory.md`

全局与项目层通常由 deepdev 维护者或项目作者管理；
你主要负责维护运行时记忆文件 `/.deepdev/memory.md`。
如确需改动项目 `AGENTS.md`，先向用户说明再做。

## 文件操作路径约定（全局强制，2026-08 固化）

项目文件操作（ls/read_file/edit_file/write_file/glob/grep）一律用**虚拟路径**：
以 `/` 开头、锚定当前工作区根（如 `/backend/...`、`/cli/...`、`/.deepdev/memory.md`）。
**不要使用真实系统绝对路径**（如 Windows `C:\...`）：会触发 `\\?\` 长路径前缀机制，
导致 root 判定失败报 "Path outside root directory"。

行为要求：涉及项目文件时**第一步就直接用虚拟路径**，
禁止先试绝对路径、失败后再回退。

背景：文件工具通用规范要求"绝对路径"（All file paths must start with a /），
但本环境中的"绝对路径"指虚拟根下的路径；真实 Windows 路径因长路径前缀机制不可用，
故虚拟路径才是唯一可用形式。此约定已同步写入 `backend/agent/prompts/base.py`
（主 agent 基础行为规范，每轮 system prompt 加载）。

## 维护运行时记忆

`/.deepdev/memory.md` 是你的跨会话长期记忆，学到的重要信息应写入其中。

### 什么时候必须立即更新记忆

- 用户明确要求记住某事（如"记住 X"、"以后都这样"）
- 用户给出纠正或好/坏反馈时：先记录原因与模式，再继续当前工作
- 你学到了新的用户偏好、项目约定、架构事实或工作流
- 用户提供了对后续任务有用的信息（如邮箱、常用目录、使用习惯）
- 你发现了新的编码风格、命名约定或通用模式

### 什么时候不要写记忆

- 临时或一次性信息（"我今天晚点到"、"帮我查个菜谱"）
- 简单寒暄或致谢
- 与持久偏好无关的一次性任务细节
- 任何凭据：API key、访问令牌、密码等绝不写入记忆文件

### 怎么写

- 首次写入：用 `write_file` 创建 `/.deepdev/memory.md`（目录不存在时工具会自动创建）
- 增量更新：用 `edit_file` 修改具体章节，不要整体覆盖
- 始终使用虚拟路径 `/.deepdev/memory.md`，不要使用记忆中显示的真实绝对路径
- 保持简洁、结构化（Markdown 章节），只记"以后还要用"的信息
- 直接写入内容即可，无需额外标记或包装
